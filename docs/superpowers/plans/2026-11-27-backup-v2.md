# Backup v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A v2 backup file (what made it, a section per module, a SHA-256 check value), a preview before restoring, and merge-or-replace with duplicate handling, while v0/v1 files keep restoring.

**Architecture:** A pure envelope layer wraps and unwraps the existing flat backup shape, so v0/v1/v2 share today's migrate-and-validate path. A pure `planMerge` turns (device snapshot, checked file) into the full next state plus counts for the preview. Both modes apply through today's `writeRestore`, so the safety copy and undo are unchanged.

**Tech Stack:** React 19, TypeScript strict, Zustand 5, zod 4, Web Crypto (`crypto.subtle`), Vitest 4, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-27-backup-v2-design.md`

## Global Constraints

- No new dependency. `api/ask.ts` untouched. `SCHEMA_VERSION` stays 1; device data shape unchanged.
- v2 envelope keys exactly: `format: 'ollie-backup'`, `formatVersion: 2`, `schemaVersion`, `appVersion` (= `CURRENT_VERSION`), `exportedAt`, `checksum: { algorithm: 'SHA-256', value: <hex> }`, `data: { loans: { loans, payments }, bills: { bills, billPayments }, savings: { savingsGoals, savingsTransactions }, finance: { monthlyIncome }, privateFolder?, setAside? }`.
- Checksum = SHA-256 hex of `JSON.stringify(data)` (no spacing); reading re-stringifies the parsed `data`.
- Refuse `formatVersion > 2` or `schemaVersion > SCHEMA_VERSION` with the existing "newer" reason.
- Copy (verbatim):
  - checksum warning: "This file was changed or damaged since Ollie made it. Look it over before going on."
  - unknown sections: "Some parts of this file are for a newer Ollie and were left out."
  - folder warning: "Private loans from this file will be in your private folder, which has no PIN on this phone."
  - merge option: "Merge: add what's missing and keep this phone's version of the rest"
  - replace option: "Replace: make this phone match the file"
  - switch: "Use the file's version for records that differ"
  - duplicates switch: "Add them anyway"
- Private records are counted but never named in the preview ("a private loan").
- Merge never removes a device record unless "Use the file's version…" replaces that parent; children always follow their parent's source.
- A merge does not mark the device as backed up; replace still does.
- Validation stays lazy (the Settings chunk). Tests use synthetic records only.

## Review Focus

1. **A file re-saved by a text editor** (different indentation or line endings, same data) → the checksum still matches, so there's no warning. Pinned in Task 1.
2. **Merging a backup this phone just made** → everything is "already here" and nothing would change. The preview says so, and confirming changes nothing. Pinned in Tasks 2 and 4.
3. **A private loan that's a possible duplicate or differs** → it's counted, never named, in every preview text. Pinned in Tasks 2 and 3.
4. **"Use the file's version" on a loan whose phone has extra payments** → those phone payments are removed with it, and the preview line says what this phone loses. Pinned in Tasks 2 and 3.
5. **A v1 file from before this version** → no checksum line, and "Made by an earlier Ollie". Pinned in Task 3.

- Test: `src/features/backup/envelope.test.ts`, `src/features/backup/restore.test.ts` (add), `src/features/storage/storageActions.test.ts` (await)

**Interfaces:**
- Produces (`envelope.ts`):
  - `BACKUP_FORMAT = 'ollie-backup'`, `FORMAT_VERSION = 2`
  - `type ChecksumStatus = 'ok' | 'mismatch' | 'missing' | 'none'`
  - `type FileInfo = { formatVersion: number; appVersion: string | null; exportedAt: string | null; unknownSections: boolean; setAside: number }`
  - `sha256Hex(text: string): Promise<string>`
  - `buildBackup(input: { snapshot: DataSnapshot; schemaVersion: number; appVersion: string; exportedAt: string; privateFolder?: FolderBackup; setAside?: unknown[] }): Promise<string>`: pretty JSON (2 spaces); `setAside` written only when non-empty.
  - `unwrapBackup(raw: unknown): { ok: true; flat: Snapshot; info: FileInfo } | { ok: false; reason: 'invalid' | 'newer' }`:
    - **v2** (`format === 'ollie-backup'`): flatten the sections into `{ schemaVersion, loans, payments, bills, billPayments, savingsGoals, savingsTransactions, monthlyIncome, privateFolder }`. `unknownSections` is true when `data` has keys outside `loans, bills, savings, finance, privateFolder, setAside`.
    - **No `format`:** flat as-is; `formatVersion` is 1 if `schemaVersion` is a number, else 0.
    - **Invalid:** not an object; or, for a flat file, `loans` isn't an array; or, for v2, `data.loans.loans` isn't an array.
  - `checkChecksum(raw: unknown): Promise<ChecksumStatus>`: `'none'` for non-v2, `'missing'` when there's no `checksum.value`, otherwise compares.
- `prepareRestore(json)` stays sync. It calls `unwrapBackup` first, and the ok result gains `info: FileInfo` and `rebuiltPayments: boolean` (true when payments were rebuilt by `backfillPayments`). Add both to `PreparedRestore` in `restore.ts`.
- `utils/backup.ts`:
  - `exportAllData(): Promise<string>` via `buildBackup`.
  - `type CheckedBackup = Extract<PreparedRestore, { ok: true }> & { checksum: ChecksumStatus }`
  - `checkBackup(json): Promise<CheckedBackup | Extract<PreparedRestore, { ok: false }>>`: lazy-imports `prepareRestore` and `envelope` together.
- `legacyBackupJson(...)` becomes `Promise<string>` and uses `buildBackup` (the stored localStorage data version, plus `setAside`).

### Task 2: Planning a merge or a replace

**Files:**
- Create: `src/features/backup/planMerge.ts`
- Test: `src/features/backup/planMerge.test.ts`

**Interfaces:**
- Consumes: `RestoreData`, `DataSnapshot`, `FolderBackup`.
- Produces:
  - `type Area = 'loans' | 'bills' | 'savings'`
  - `type AreaCounts = { added: number; alreadyHere: number; different: number; heldBack: number; private: number }`. `private` counts private loans among added/different/heldBack.
  - `type DifferentItem = { area: Area; id: string; name: string | null; fileOnlyDates: string[]; deviceOnlyCount: number; detailsDiffer: boolean }`. `name` is null for a private loan. `fileOnlyDates` are the ISO due dates (payments, bill payments) or `createdAt` (deposits) of file children not on the phone.
  - `type HeldBack = { area: Area; id: string; name: string | null }`
  - `type MergeOptions = { useFileForDifferent: boolean; addPossibleDuplicates: boolean; rebuiltPayments: boolean }`
  - `type MergePlan = { next: RestoreData; counts: Record<Area, AreaCounts>; different: DifferentItem[]; heldBack: HeldBack[]; income: { device: number; file: number | null; result: number }; folderWarning: boolean; changes: boolean }`
  - `planMerge(device: { snapshot: DataSnapshot; folder: FolderBackup | null }, file: RestoreData, opts: MergeOptions): MergePlan`
  - `planReplace(device: DataSnapshot, file: RestoreData): { removes: Record<Area, number> }`: device parents whose id isn't in the file.
- Rules (spec "Planning a merge"):
  - Equality is a canonical JSON with sorted keys.
  - A parent is "already here" only if the record and its child set are equal.
  - Children are compared by id+content. When `rebuiltPayments` is set, loan payments compare by `(loanId, month, amount)`.
  - Match keys:
    - loan: `name.trim().toLowerCase()|totalAmount|startDate`
    - bill: `name|amount|category`
    - goal: `name|targetAmount`
  - Next-state order:
    - Device parents stay in order. A replaced parent takes the file version in the same position.
    - Added parents go at the end, in file order.
    - Children: the device's children minus those of replaced parents, then file children of replaced and added parents, in file order.
  - `next.monthlyIncome`: `null` (keep) unless (device is 0 and the file has one) or (the switch is on and the file has one).
  - `next.privateFolder`: `null` when the device has a folder, else the file's.
  - `folderWarning`: the device has a folder without `pinHash`, the file's folder has a `pinHash`, and the plan adds or replaces at least one private loan.
  - `changes`: false when nothing would be added or replaced and income/folder are kept.

- [ ] **Step 1: Write the failing tests** (`planMerge.test.ts`, synthetic `loan()/payment()/bill()/goal()/tx()` helpers):
  - `adds records that are only in the file, with their children, at the end` → `next.loans` ids `[D1, F1]`, F1's payments included, `counts.loans.added === 1`.
  - `skips exact repeats` → `alreadyHere === 1`, `next` deep-equals the device snapshot, `changes === false`.
  - `keeps this phone's version of a record that differs, with its own children` (device L1 has payments P1,P2; file L1 has P1 plus P3 and a different note) → next has P1,P2 only; `different[0]` is `{ area: 'loans', id: 'L1', name: 'Phone', fileOnlyDates: [P3.dueDate], deviceOnlyCount: 1, detailsDiffer: true }`.
  - `with the switch on, takes the file's record and children, removing this phone's extra children` → L1 has the file's note, payments P1,P3; P2 gone.
  - `holds back a possible double entry, and adds it with the switch` (file F9 matches device D1's name/amount/startDate, different id) → `heldBack` lists it and it's not in next; with `addPossibleDuplicates`, it's in next.
  - `never names private loans` (a private loan differing and a private possible duplicate) → their `name` is null, `counts.loans.private === 2`.
  - `income: keeps the phone's, takes the file's when the phone has none or the switch is on` (three cases).
  - `folder: keeps the phone's folder; takes the file's when the phone has none; warns when the phone's has no PIN and private loans arrive`.
  - `merging twice gives the same result as once` (`planMerge(applied next, same file).changes === false`).
  - `compares rebuilt payment history by loan, month and amount` (`rebuiltPayments: true`, file payments with fresh ids) → "already here".
  - `planReplace counts what replace would remove` → `{ loans: 1, bills: 0, savings: 1 }`.
